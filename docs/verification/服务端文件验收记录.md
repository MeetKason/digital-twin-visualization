# 服务端文件验收记录

日期：2026-11-09（Asia/Shanghai），基于 0.2.0 服务端基础版继续建设。界面来源仍仅为 Figma 新电子沙盘。

## 本轮实现

- 模型、视频、PDF 新上传存入服务器受控目录；租户由服务器会话决定，场景和角色授权与业务 API 相同。文件路径只使用散列作用域及随机 ID，不使用原文件名。
- 二进制流式接收，上限 100MB；同时最多两个上传。检查文件头、glTF 版本及外部资源，GLB/GLTF 禁止外部 URI。无效/超限/中断上传清理暂存目录；拒绝上传后关闭该连接，避免未读数据影响连接复用。
- 目录原子重命名后才返回文件标识；新业务保存校验文件存在、作用域、类型、大小与名称。业务保存和删除共用场景锁，禁止删除仍被引用的文件。
- 前端先确认业务保存成功再选择模型或删除文件；失败上传尝试回收。未关联文件列表提供物理删除重试入口，服务器再次检查引用。
- 旧 IndexedDB 文件可原地读取并逐项迁移；不会静默上传或删除旧文件。跨浏览器需要同租户真实账号，独立演示会话不共用工作区。
- Compose 增加文件卷，Nginx 放行受限大文件上传；备份停止写入端后导出数据库及文件，成套校验恢复。账号、地图和环境配置需另行保管。
- 依赖锁文件的 456 个认证镜像地址改为 npm 公共地址；包版本与 integrity 完全一致。干净容器实际执行 npm ci 并完成两个镜像构建。

## 容器演练范围

本机为 Apple Silicon，Web/API/Worker 镜像原生构建，PostGIS 16-3.5 使用 amd64 模拟。直接挂载 Documents 及临时目录均停在 Docker 启动阶段；验证脚本改为把相同迁移和配置字节复制到隔离容器/命名卷，避免主机文件共享。此结果验证应用、数据库、文件持久化与备份恢复链路，不覆盖正式 Compose 的主机 bind mount 权限、目标 Linux/CPU 架构、断网安装或现场安全验收。

首次镜像构建因旧认证源返回 E401 而失败，改公共下载地址后干净容器 npm ci 与镜像构建通过。临时容器验证脚本曾把迁移目录复制成子目录，导致表未初始化；修正为复制目录内容后，完整流程通过。上述失败均已修正或明确限定，没有把失败的运行记作通过。

## 限制

当前为单 API 实例文件服务；应用内场景锁不能支持多个 API 实例并发写入。尚无病毒扫描、租户容量配额、对象存储、自动垃圾回收、断点续传或视频转码。文件头及 glTF 校验不等同完整内容安全扫描；不能泛称生产安全验收通过。

进程被强制终止可能留下 `.upload-*` 暂存目录，需维护窗口人工检查；正常失败和连接中断会清理。未关联文件可由有写权限的账号显式清理。旧浏览器文件未迁移前仍只在原浏览器可用。

真实天擎、采集水位线/补数、API 消费入库观测、正式地图与设备数据、许可证及目标环境离线升级验收仍未完成，见架构完成度清单。生产启动保护继续启用。

# 当前可完成的架构待办设计

## 意图

沿用总体技术方案推进五项可在本地 Mock 环境完成的工作：性能基线、采集缺测与告警、插件发现/校验、核心业务实体与发布、离线升级交付。

## 目标与边界

- 提供可重复的浏览器性能报告，分别记录地图首屏、图层加载和模型上传/预览耗时；基线记录环境和分位数，不用跨机器硬编码阈值。
- 采集健康摘要使用服务端租户/场景范围，明确区分待执行、失败和真正缺测；无真实来源时所有模拟指标标记 Mock。
- 插件从静态同源目录发现，严格校验清单、完整性哈希和 SDK 主版本；禁止任意 URL、远程源和未校验代码。数字签名及授权策略等密钥/商业政策未给定，不伪造。
- 对站点、方案、书签、模型资产做版本化关系表与既有 JSONB 双写/回填；新增管理员发布快照，保留修订和发布者，避免破坏旧客户端及历史数据。
- 离线包包含版本化镜像、部署文件、迁移和校验清单；升级前必须备份，回滚使用之前的镜像和数据库/文件成套备份；提供隔离环境离线验收。

## 方案与决策

1. 数据关系表采用一次性替换 JSONB 或渐进式双写。选择渐进式双写：风险更低、旧版兼容；关系表作为查询/发布投影，JSONB 暂保留完整工作态。
2. 插件包采用任意远端 URL、数字签名基础设施或同源清单+SHA-256。选择同源清单+SHA-256 及 SDK 兼容校验；签名密钥和许可证规则尚未提供，保留扩展位并明确限制。
3. 性能验证采用 CI 硬阈值或可重复测量报告。选择报告加宽松的功能/数据完整性断言，避免将单机波动误判为回归。

## 验收

性能脚本输出浏览器、平台、运行次数和 p50/p95；健康接口隔离租户并覆盖任务失败/积压/缺测；插件测试拒绝错误哈希、恶意路径、重复 ID 和不兼容 SDK；数据库测试从旧 JSONB 回填、CAS 保存并生成不可变发布版本；离线包验证校验和、镜像标签、无秘密配置，并可在禁止拉取镜像的隔离 Compose 中启动及执行健康检查。

# 系统管理子菜单授权设计

## 目标

平台最高管理员可管理全部功能；其他账号仅能看到并调用获准的系统管理子功能。地区场景包定义功能上限，账号授权定义个人范围，最终取交集。菜单隐藏与服务端拒绝必须一致。

## 约束与兼容

- 沿用现有场景包、账号、会话与 Ant Design 界面；不新增数据库表。
- 场景包和账号新增可选 `settingsSections`。旧场景包按全部子菜单读取；旧管理员账号按全部子菜单读取，旧编辑员和只读账号不授予管理子菜单。
- 平台最高管理员和隔离演示管理员保留全量入口，不受地区场景包配置影响。
- 子菜单授权只收窄既有角色权限；不会让编辑员获得管理员 API 权限。
- 直接调用账号、场景包、发布、审计及采集管理接口时，服务端也校验相应授权；地图与站点等共用业务 API 继续由原有角色和模块权限保护。

## 方案

场景包编辑器增加“系统管理子菜单”多选；账号开通与编辑增加同一组多选。服务端为 `/api/scenes` 返回当前用户生效的子菜单集合；前端只显示该集合，并在集合为空时隐藏主导航“系统管理”。场景包发布或账号授权变更后重新计算，不信任浏览器提交的权限字段。

## 备选方案

- 只按场景包配置：无法区分同地区账号，未采用。
- 只按账号配置：无法为地区设置功能上限，未采用。

## 验收

最高管理员全量可用；受限管理员只能看到交集；无系统管理授权的账号不出现入口；受限账号直接访问对应管理 API 返回 403；旧配置可正常读取。

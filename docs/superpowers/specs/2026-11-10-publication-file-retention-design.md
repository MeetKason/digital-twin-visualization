# 发布历史文件保留

按照既有总体方案补齐发布快照与文件生命周期的关联。当前草稿删除附件引用后，任意保留的发布快照仍能恢复，因此这些快照引用的文件必须继续保留。

采用完整历史引用检查：文件仓库直接扫描当前租户、地区的所有快照；PostgreSQL 使用带租户和地区条件的 JSONB 资产引用聚合。不能复用最多100条的展示查询。删除沿用现有场景锁，先检查草稿、再检查历史引用；无法读取引用信息时拒绝继续删除。清理清单同时返回草稿、发布历史引用标记，前端仅展示真正未关联的文件，并显示历史保护数量。

保留所有审批状态的快照引用，不自动删除历史、附件或引入保留期限。仍为单实例场景锁；跨实例一致性待后续存储架构实现。

验证覆盖102条历史时的最旧文件、租户地区隔离、服务重启后保护、HTTP删除拒绝、未关联文件可删除，以及历史恢复时附件仍可下载。

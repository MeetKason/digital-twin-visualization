# 逐项达到可演示标准

根据用户确认的缺口表执行，沿用现有架构，先完成高优先级再推进扩展能力。禁止把 Mock 效果表述为正式业务产品；不覆盖既有业务资料；本轮不部署。

1. 地图稳定性：地形请求具备可取消排队/超时/重试、缓存和释放；切换场景取消配置请求；单块影像失败不立即撤掉整幅卫星图。测试覆盖并发、取消、授权失败、断网恢复和快速切换。
2. 气象展示：雷达和云图以连续栅格显示，风场按方向与速度显示箭头；预报明确起报/有效时间/时效。演示和入库接口沿用同一契约；无值保持透明，不生成替代资料。
3. 演示资料：模型、视频、PDF进入按租户/场景授权的文件仓库；书签和路线已有预置，在其基础上增加可重复的新演示会话初始化流程。正式账号、已有修订不自动覆盖。
4. 会话与回归：保留上一轮的统一401处理和19项浏览器回归，增加本轮端到端场景。
5. 后续按顺序：运行时场景包与模块配置；插件扩展点及独立服务模板；租户/项目与模块数据授权；站点字典、字段模板和导入报告；设备告警地图与模拟视频联动。真实设备/天擎和客户许可证签发材料后期接入。

每项先写可失败的测试，再实现；阶段验收执行 npm run check 与 npm run test:e2e，更新中文README及验收记录。尚未完成的能力保留明确状态，不将整个清单泛化标记为完成。
